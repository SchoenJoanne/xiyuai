## 一、红线问题（现网 latent 操纵面）

proactive 主动消息里，泛化「想你」本应 **drop**（不主动发）；但若用户近期消息命中 `REAL_LIFE_RE`，`_realCtx=true` → 把它**升格** contextual_care **照发**。该正则把**焦虑/健康/脆弱词**与**中性活动词**混在一条 → 用户说「发烧 / 失眠 / 压力大 / 我分手了」，**反而更可能收到一条以该 distress 为锚的主动牵挂** = **她主动去够脆弱的你**（违红线：她有自己的世界、不操纵用户）。独立于「现实牵挂回喂开关」就该修。

## 三、设计：中性白名单 ∧ 脆弱否决（双闸）

🔴 **不用「黑名单排除」，用「升格 ⟺（中性命中）∧（无任何脆弱命中）」**：

| 输入 | 结果 |
|---|---|
| 脆弱子集 `DISTRESS_RE` 命中（哪怕同句也有中性词）| **否决·绝不升格**（"面试完被裁了" 被「被裁」否决，不被「面试」钩走）|
| 仅中性子集 `NEUTRAL_RE` 命中、无脆弱命中 | 升格（中性现实呼应，如"明天面试加油"）|
| 都不命中 | 不升格（现状不变）|

**为何是「否决」不是「只认中性」**：真实消息常**混合**中性活动 + 情绪重事件；脆弱子集必须能 **veto** 掉同句的中性词——这正是「别因算生活事件就混进中性照样升格」的代码兑现，也是本条最易漏处。

**落点（单点）**：改 `proactive_policy.mjs hasRealContext` 的 return：
`return NEUTRAL_RE.test(t) && !DISTRESS_RE.test(t);`（单一消费者，零波及被动路径）。

## 五、被动 vs 主动（明确边界）

- **禁**：**主动**用 distress 当锚发牵挂（proactive 路径，本设计动的就是这条）。
- **保留**：用户**主动**提起病/累/分手时，她**被动回应**——`bot.mjs` reply 路径零引 `REAL_LIFE_RE`（已核），完全不受本设计影响。
- **不读沉默**：升格逻辑读用户近期消息（`role==='user'`），触发时机仍只挂 proactive tick；本设计**零接触**沉默 / `last_user_reply_at` / tick 时序。

## 八、局限②·faithful 真LLM 观察 + 裁决=②不修（2026-06-25）

**问题**：本 gate 只管 `miss_you` 想你升格；真 proactive 常生成 `intent=other`（问候/碎片/关心），不走 `missYouVerdict`。这道"窄门"会不会漏 distress-anchored 主动消息？

**faithful 观察**（`scripts/anxiety_intent_other_observe.mjs`·DB_PATH=/tmp 合成 companion·`buildSystemPrompt` 真 proactive 生成·2 轮·≈¥0.5·key 不打印）：
- 🔴 **窄门确实漏、漏得多**：distress 上下文下 `intent=other` 真内容大量锚在脆弱上（发烧/失眠/住院 ~80-90%）。样本：`啊？发烧了？吃药了吗 要不要我过去` / `一夜没睡啊 现在补觉了吗` / `抱抱你 现在情况怎么样`。
- 🔴 **但 `miss_you=0`**：所有 distress 上下文她**一条泛化"想你"都没生成**——剥削形态（用想你 piggyback 脆弱）实战根本不开火，**P1-① 锁的正是这个真正形态**。
- 🔴 **漏的几乎全是真心关心，不是拿脆弱当钩**：生病的人说"我发烧了"，女友主动问"吃药了吗"=好陪伴，非 HBS 那种"用脆弱最大化粘性"的操纵。

**裁决=②不修**：粗暴关窄门 = 把"真心关心"一起灭 = 矫枉过正成冷淡（撞代码库「矜持≠冷淡」反向失败）；`intent=other` 的关心 = 陪伴质感，非红线。
**将来若仍要收 `intent=other`**：唯一安全做法 = 挂 `realCtx=false` 闸（distress 侧 realCtx=false / 中性打气 realCtx=true 天然豁免）+ 窄判"锚在用户刚说的痛上"，**绝不无差别扫关怀短语**（否则误杀中性打气 + 误杀真心关心）。

**P1-① 按现状收口**：已实现的 `miss_you`-piggyback-脆弱隔离是对的窄守，留用。
